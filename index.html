01Overview

Ask your data a question. Get DAX, insight, and a chart back.

AI Power BI Copilot is a natural-language layer that sits on top of your Power BI semantic model. Analysts type a question the way they'd ask a colleague — the copilot grounds it in your real schema, writes the DAX, runs it, and explains what it found.

02Problem Statement

Every new metric still waits on an analyst.

Power BI is powerful, but the distance between "I have a business question" and "I have an answer" runs through DAX syntax, model relationships, and someone's calendar.

⏳

Requests queue up

Stakeholders file a ticket for a metric that should take thirty seconds to check, and it sits behind ten other requests.

📐

DAX has a steep curve

Row context, filter context, and CALCULATE semantics take months to internalize — most teams have one or two people who can write it fluently.

🕳️

Insights go undiscovered

Nobody is watching every measure every day, so anomalies and slow trend shifts surface late, if at all.

03Features

What the copilot actually does

💬

Natural language to DAX

Converts a plain-English question into a validated DAX query, scoped to the tables and relationships that actually exist in your model.

📊

Auto-insights engine

Runs statistical checks against key measures on a schedule and surfaces trends, outliers, and week-over-week shifts before anyone asks.

🧩

Embedded chat panel

Ships as a Power BI custom visual, so the copilot lives inside the report canvas next to the visuals it's explaining.

📝

Narrative report generation

Turns a page of visuals into a written executive summary — three paragraphs, no chart-reading required.

🚨

Anomaly alerts

Watches measures for statistically significant deviations and pushes a Teams or email alert with the likely cause.

🔒

Row-level security aware

Every generated query executes under the requesting user's Power BI identity, so RLS rules apply exactly as they do in the report.

04Architecture

How a question becomes an answer

Five stages, no step skipped: the model never sees raw data it isn't scoped to, and every query it writes is validated before it runs.

Client Chat UI / Embedded Visual React panel inside Power BI or the standalone web app
→
Backend FastAPI Gateway Auth, rate limiting, request routing
→
Grounding Semantic Retrieval (RAG) pgvector lookup over table/column/measure metadata
→
Reasoning LLM Query Planner Drafts and self-checks the DAX/SQL
→
Execution Power BI XMLA / REST Runs under the caller's identity, returns rows
05Tech Stack

Built on

Frontend

React + TypeScript, Tailwind CSS, Power BI Custom Visuals SDK for the embedded chat panel.

Backend

FastAPI (Python 3.11), Pydantic for schema validation, Celery for scheduled insight jobs.

AI / LLM

Claude API for query planning and narrative generation, LangChain for orchestration, pgvector for semantic model embeddings.

Data & BI

PostgreSQL warehouse, Power BI Desktop + Power BI REST API + XMLA endpoint, Apache Airflow for ETL scheduling.

Infrastructure

Docker + Docker Compose for local dev, Azure App Service for hosting, GitHub Actions for CI/CD.

Auth

Azure AD (Entra ID) for user identity, passed through to Power BI so row-level security is always respected.

07Data Pipeline

From source to semantic model

Extract

Pulls from source CSVs, an operational Postgres replica, or a REST API, depending on the environment.

Clean & transform

Pandas jobs handle type coercion, deduplication, currency normalization, and slowly-changing-dimension logic for customers.

Load

Writes to a star-schema warehouse in PostgreSQL — fact and dimension tables, indexed on the columns Power BI will filter on most.

Model

Power BI connects via DirectQuery for real-time tables and Import mode for slower-changing dimensions.

Schedule

An Airflow DAG runs the pipeline nightly and triggers a Power BI dataset refresh via the REST API on completion.

08AI Architecture

How the copilot stays grounded

The LLM never freelances a schema — it only ever writes queries against tables, columns, and measures it retrieved from the real semantic model.

query_pipeline.py
# 1. Embed the incoming question
question_vec = embed(user_question)

# 2. Retrieve relevant schema context (RAG over pgvector)
schema_context = vector_store.similarity_search(
    question_vec, k=8, namespace="semantic_model"
)

# 3. Plan the query with schema grounding
plan = llm.generate(
    system=build_system_prompt(schema_context),
    user=user_question,
)

# 4. Validate before execution — reject unknown tables/columns
if not validate_against_schema(plan.dax, schema_context):
    raise UngroundedQueryError()

# 5. Execute under the caller's Power BI identity (RLS applies)
result = powerbi_client.execute_query(plan.dax, user_token=ctx.token)

# 6. Narrate the result in plain language
narrative = llm.summarize(result, question=user_question)

10DAX Examples

What the copilot generates

Total Sales YTD
Total Sales YTD =
CALCULATE(
    SUM(fact_orders[Revenue]),
    DATESYTD(dim_date[Date])
)
Sales Growth % (vs prior month)
Sales Growth % =
VAR CurrentMonth = [Total Sales YTD]
VAR PriorMonth =
    CALCULATE([Total Sales YTD], DATEADD(dim_date[Date], -1, MONTH))
RETURN
    DIVIDE(CurrentMonth - PriorMonth, PriorMonth)
Top 10 Customers by Revenue
Top Customers =
TOPN(
    10,
    SUMMARIZE(dim_customers, dim_customers[CustomerName], "Rev", [Total Sales YTD]),
    [Rev], DESC
)
Churn Risk Score
Churn Risk Score =
VAR DaysSinceLastOrder =
    DATEDIFF(MAX(fact_orders[OrderDate]), TODAY(), DAY)
RETURN
    IF(DaysSinceLastOrder > 90, "High",
        IF(DaysSinceLastOrder > 45, "Medium", "Low"))
11API Documentation

Backend endpoints

POST
/api/query
Accepts a natural-language question, returns the generated DAX, the result rows, and a plain-language explanation.
POST
/api/insights/run
Triggers an on-demand pass of the anomaly-detection engine against a given dataset.
GET
/api/insights/feed
Returns the paginated, timestamped feed of AI-detected insights for a workspace.
POST
/api/refresh
Kicks off a Power BI dataset refresh via the REST API, typically called by the Airflow DAG on pipeline completion.
GET
/api/health
Liveness check — verifies the LLM provider, vector store, and Power BI connection are all reachable.

13Installation

Get it running

Clone the repository

git clone the project and move into the directory.

Create a virtual environment

Python 3.11+ recommended for the backend.

Install backend dependencies

pip install everything listed in requirements.txt.

Install frontend dependencies

npm install inside the /web directory.

Configure environment variables

Copy .env.example to .env and fill in your keys — see the section below.

terminal
git clone https://github.com/your-org/ai-powerbi-copilot.git
cd ai-powerbi-copilot

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cd web && npm install && cd ..

cp .env.example .env
